# Correctness evidence

Keep existing tests independent from generated implementation code. Test normal inputs, boundaries, errors, wrong types, mutation, and interface behavior. Differentially compare return types and values, exceptions and messages, stdout/stderr, exit codes, serialized data, and externally observable effects as applicable. Use explicit tolerances or normalization only when the contract requires them.

The development CLI compares Python scalar/container results with type tags, dictionary insertion order, exceptions, captured stdout/stderr, and post-call positional/keyword argument values on supplied JSON cases. Mutations before an exception count too. It runs independent tests, observations and timing in separate disposable copies/processes; workloads must provide their own inputs rather than relying on test-generated setup. It rejects known zero-test output from unittest/pytest. Arbitrary custom runners remain the user's responsibility. Legacy observation schema 1 remains readable but cannot prove mutation equivalence; replay is required for schema-2 evidence.

It does not prove general equivalence. It does not compare file mutations, network behavior, concurrency, identity, aliasing, timing behavior, function metadata, or arbitrary Python objects. Add independent evidence for these before expanding the adapter. Generated tests are supplemental evidence, never a substitute for independent expectations.

For a port that another tool switches on and off at run time, such as a rust-anything port (`RUST_ANYTHING_MODE=old|new`), `oxidize crosscheck PROJECT -- <command>` runs the application command both ways in fresh disposable copies (sandboxed unless `--trust-code`). It compares exit code, stdout, stderr and the files named with `--file`, and times only commands that agree. A difference exits 2. It sees only what those commands do with those inputs; see [Oxidize and rust-anything](../../../docs/RUST_ANYTHING.md).
