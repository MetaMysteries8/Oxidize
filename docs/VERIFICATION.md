# Verification and performance evidence

The initial demo's independent Python tests cover known prime counts, all limits below 200 against a separate `math.isqrt` reference, and errors for negative/huge integers and noninteger inputs. Eleven supplied differential cases cover boundaries, an actual compute workload, error types/messages, and keyword invocation. PyO3 builds in release mode; the application calls the extension through the original Python interface.

Standard Cargo tests cover config roundtrips/validation, path traversal and secret exclusions, source snapshots/fingerprints, symlink rejection, process timeout/output bounds, static language/graph/plan output, no-execution AST inspection, session locking/recovery/source-edit detection, baseline test failures, evidence capture, fail-closed sandbox behavior, HTTP rate-limit retry/usage parsing and portable skill structure.

Opt-in native tests actually compile and load the PyO3 implementation. They exercise acceptance, independent-test rejection of compilable wrong code, saved-state resume with corrected code, preservation of partial attempts, and rollback. A separate deterministic HTTP integration test exercises compiler-guided model repair. Neither uses a paid provider.

Measurement uses Python `perf_counter_ns` in independent original/candidate processes, two warm-up batches and seven measured batches by default. It measures successful supplied cases through the Python callable; errors are checked separately. Each batch reconstructs case arguments to avoid mutation leaking between repetitions. The report contains raw samples, median and median absolute deviation. Input reconstruction, Python call dispatch and FFI are included in both sides' timings. Sequential ordering and machine noise can bias results. These timings do not measure startup, whole-app throughput, CPU use, allocations or memory; no such metrics are fabricated.

Exact comparisons currently preserve scalar types, list/tuple distinctions, dict order, exceptions and stdout/stderr. Non-finite floats and arbitrary objects fail instead of being silently normalized. Mutation, external side effects, timing/concurrency, import races, reflection/docstrings/annotations, Python object identity and unsupported calls remain unverified. Passing tests and cases is bounded evidence, not a mathematical proof of equivalence.
